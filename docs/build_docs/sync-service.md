## Rate Limit Handling

When the GSMArena Parser secondary API hits its rate limit, the service logs warnings and falls through to the next provider:

```
[2026-01-24T02:17:08] ERROR [ExternalApiService] Request to gsmarenaparser.p.rapidapi.com failed: 429 - You have exceeded the rate limit per minute for your plan, BASIC, by the API provider
[2026-01-24T02:17:08]  WARN [ExternalApiService] Secondary specs fetch failed for Apple Watch Series 10 Aluminum: External API Error from gsmarenaparser.p.rapidapi.com: You have exceeded the rate limit per minute for your plan, BASIC, by the API provider
[2026-01-24T02:17:08]  WARN [SyncService] Failed to sync device Watch Series 10 Aluminum: Device specifications not found in any selected provider
```

This pattern repeats for each device when all providers are rate-limited:

## Key Observations

- **Smart Sync** is enabled: the service caps "Deep Sync" fetches to 5 per session to preserve monthly API quotas.
- **Request throttling**: 5-second delay between API hits to respect rate limits.
- **Provider fallback**: Primary (Phone Specs Explorer), Secondary (GSMArena Parser), Tertiary (Mobile Phones2).
- **Fill Gaps logic**: Only populates missing fields on existing devices to preserve manual edits.
- **Rate limits** on the BASIC plan trigger 429s frequently during bulk sync — this is expected behavior; the sync continues for devices where data was already fetched.
