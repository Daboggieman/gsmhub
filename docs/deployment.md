# GSMHUB Deployment Guide (Render, free stack)

Deploys the full stack on Render's free tier: Next.js frontend + NestJS
API + Key Value (Redis) cache, with MongoDB on Atlas's free M0 cluster.
No custom domain required — you deploy on `*.onrender.com` subdomains and
attach a domain later without re-architecting (see "Adding your custom
domain" at the end).

Architecture note: the frontend proxies browser API calls through
same-origin `/api/*` (see `next.config.ts` rewrites), so the auth cookie
stays first-party. Cross-site cookies would break admin login on Safari
and Brave — don't bypass the proxy by pointing the browser at the API URL
directly.

---

## 1. MongoDB Atlas (free)

1. Create an account at <https://www.mongodb.com/cloud/atlas> → build an
   **M0 (Free)** cluster.
2. **Database Access**: create a database user (username + generated
   password).
3. **Network Access**: allow access from anywhere (`0.0.0.0/0`) — Render's
   free services have shared, rotating egress IPs, so IP allow-listing
   isn't possible.
4. Copy the connection string:
   `mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/gsmhub?retryWrites=true&w=majority`

## 2. Render (Blueprint)

1. Push this repo to GitHub (Render deploys from Git).
2. Render Dashboard → **New → Blueprint** → select the repo. Render reads
   [`render.yaml`](../render.yaml) and creates three resources:
   - `gsmhub-api` (NestJS web service)
   - `gsmhub-cache` (Key Value, free)
   - `gsmhub-web` (Next.js web service)
3. When prompted for `MONGO_URI`, paste the Atlas connection string.
   `JWT_SECRET` is generated automatically.
4. Wait for the first builds. Free-plan builds take a few minutes.

Service URLs end up like `https://gsmhub-api-xxxx.onrender.com` and
`https://gsmhub-web-xxxx.onrender.com` (visible on each service page).

## 3. Seed the database (run once, from your machine)

```bash
pnpm install
pnpm --filter @gsmhub/shared build

# Admin + demo data (adjust flags as needed — see src/seed.ts)
MONGO_URI='<atlas-uri>' pnpm --filter backend run seed:gsma

# Device catalog from the PhoneDB dataset
MONGO_URI='<atlas-uri>' PHONEDB_JSON='<path-to-dataset.json>' \
  pnpm --filter backend run seed:phonedb

# Price history rows for the seeded devices
MONGO_URI='<atlas-uri>' PHONEDB_JSON='<path-to-dataset.json>' \
  pnpm --filter backend exec ts-node -r tsconfig-paths/register --transpile-only src/seed-prices.ts
```

Alternatively, seed via the admin panel later (Devices → Bulk Import CSV,
per-device Sync) once an admin user exists.

## 4. Create the first admin

With the API running, create the owner account directly against Atlas
(insert a user with role `admin` and a bcrypt hash — or temporarily start
the backend locally pointed at the Atlas URI and register through the
normal flow, then promote the role in Atlas).

## 5. Post-deploy checklist

- [ ] `https://<gsmhub-api-url>/health/live` → `{"status":"ok",...}`
- [ ] `https://<gsmhub-api-url>/health/ready` → `{"status":"ok"}` (proves Mongo connectivity)
- [ ] Frontend loads; device search returns results (proves the `/api` proxy works)
- [ ] **Admin login works in Safari/Brave, not just Chrome** (proves first-party cookies)
- [ ] `/robots.txt` and `/sitemap.xml` render
- [ ] `/privacy`, `/terms`, `/about`, `/contact`, `/ads.txt` all respond (AdSense prerequisites)
- [ ] No `/test-devices` route (removed — thin content hurts ad review)

## 6. Environment variables (reference)

### gsmhub-api (backend)

| Key | Source | Notes |
| --- | --- | --- |
| `MONGO_URI` | Atlas (prompted) | include the `gsmhub` database name |
| `JWT_SECRET` | auto-generated by blueprint | ≥ 32 chars |
| `REDIS_URI` | from `gsmhub-cache` | wired by blueprint |
| `FRONTEND_URL` | from `gsmhub-web` | CORS allow-list; host-only values get `https://` prepended |
| `NODE_ENV` / `NODE_VERSION` / `PORT` | blueprint / Render | `PORT` is injected by Render |

Auth cookies: defaults (lax, no domain) are correct under the same-origin
proxy. Do **not** set `COOKIE_SAME_SITE=none` — that's only for split
origins, which this architecture avoids.

### gsmhub-web (frontend)

| Key | Source | Notes |
| --- | --- | --- |
| `BACKEND_URL` | from `gsmhub-api` | SSR calls + the `/api` proxy destination |
| `NEXT_PUBLIC_SITE_URL` | set after first deploy | set to the frontend's own `https://...onrender.com` URL; robots.txt + sitemap advertise it |
| `NEXT_PUBLIC_ADSENSE_ID` | after AdSense approval | enables the loader script |
| `NEXT_PUBLIC_ADSENSE_PUBLISHER_ID` | after AdSense approval | makes `/ads.txt` serve the real record |

Note: `NEXT_PUBLIC_*` values are **build-time** — after changing one,
trigger a manual redeploy of `gsmhub-web`.

### Local development

Unchanged: backend on `localhost:3001`, frontend `next dev` proxies
`/api` to it via `BACKEND_URL` (default `http://localhost:3001`).

## 7. Adding your custom domain (later)

1. Buy the domain (e.g. `.com.ng` — see docs/monetization-setup.md).
2. Render → `gsmhub-web` → **Settings → Custom Domains** → add it; add the
   `CNAME` record at your registrar as instructed. Do the same for
   `gsmhub-api` if you want `api.<domain>` (optional — the proxy means the
   API can stay on its onrender URL).
3. Update `NEXT_PUBLIC_SITE_URL` on `gsmhub-web` to `https://<domain>` and
   redeploy (robots/sitemap follow).
4. Update `FRONTEND_URL` on `gsmhub-api` if you exposed the API directly.
5. Then finish AdSense: set `NEXT_PUBLIC_ADSENSE_ID` +
   `NEXT_PUBLIC_ADSENSE_PUBLISHER_ID`, verify `/ads.txt` serves the
   record, and continue from docs/monetization-setup.md Stage 1.

## 8. Known free-tier trade-offs

- **Cold starts**: free web services spin down after ~15 min idle; the
  first request takes ~50s (frontend) / ~1 min (API). Acceptable while
  traffic is low; upgrading later is one click per service.
- **Render free Key Value** has no persistence (`persistenceMode: off`) —
  it's a cache; a restart just warms it up again.
- **Atlas M0** caps at 512MB storage; watch for it as the catalog grows.
